# AVORA V13.1 Pilot Test Protocol

## Purpose
Test whether real JSS learners understand what each question asks, can follow the board/voice pacing, and receive useful correction after an error.

## Minimum pilot
- 3–5 learners per tested class level, plus at least 1 practising Mathematics or English teacher reviewing each tested subject.
- Start with 2 Mathematics topics and 2 English topics across different skill types.
- Do not use pilot success to claim whole-curriculum validation.

## Observe, do not coach
For every lesson/checkpoint record:
1. Did the learner understand the command without asking what the question meant?
2. Did the learner know what form the answer should take?
3. Did board writing appear before/with the matching narration rather than all at once?
4. Was the pace too fast, too slow, or appropriate?
5. On a wrong answer, did AVORA preserve correct work and identify the first meaningful gap?
6. Did the hint help without revealing the answer?
7. After help, could the learner solve a fresh equivalent question independently?

## Release thresholds for a tested question
- 100%: one unambiguous task and a defined marking strategy.
- 100% MCQ: four unique options and exactly one defensible keyed answer.
- >=90% pilot learners understand the task without adult reinterpretation.
- Any teacher finding of two defensible answers, missing information, wrong key, or curriculum mismatch blocks that item.

## Evidence to retain
Question ID, topic, learner class, anonymised attempt, confusion flag, hint used, final result, teacher-review decision, and correction made. Never retain unnecessary child-identifying data in research notes.
